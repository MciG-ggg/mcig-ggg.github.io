第 1 章 Code Review 在流程中的位置（V3 00:00-02:23）

- 公司规则：工期超过三天的开发任务都要 code review [00:00]
- 潜规则的代价：赶进度让「能跑就行」，上线后代码质量差、运行性能差；程序员离职后接手的人看不懂；本想改一个小 bug 却多出三个 bug [00:30]
- 定义：对别人写的代码做审核，确保开发质量，是项目质量管控的重要环节 [00:45]
- 位置：开发结束、准备提测之前 [00:50]
- 顺序：需求 → 设计（设计也要评审）→ 写代码 → code review → 提测 [01:00]
- 提测阶段不应该大量改代码，只该完善：改 QA 提的 bug、兼容极端与边界问题 [01:15]
- 参与角色：代码开发者、技术能力强的人（开发组长、架构师）、QA [01:40]
- QA 为什么要在场：很多 QA 也写代码；听你讲的时候会想「这样做是否符合产品需求」「我设计的测试 case 有没有漏」「这个判断条件是不是全的」「哪些场景会跳过这些判断」[02:00]
- code review 顺便确定本次改动的范围，QA 只测相关业务逻辑 [02:20]
