# 文章大纲模板 (Templates)

6 种文章类型，按用户脑中的题材分类。落盘时再选 `note/` 或 `jotting/` 集合。

---

## 1. 年度总结 (Annual Recap)

**适用场景**：学期/学年/年度复盘，反思成长与方向。

**真实样本**：`note/zh-cn/大一下学期总结.md`、`jotting/zh-cn/3月月总结.md`

**大纲骨架**：

```markdown
## 学习
- 这学期/今年看了什么书/课/论文
- 哪个方向最终没走通（坦诚说）
- 哪个方向出乎意料有进展

## 折腾
- 报了哪些项目/比赛/活动
- 哪些成了、哪些黄了

## 人与关系
- 认识了谁、谁对我影响大
- 不需要写谁名字太具体，留"某人"即可

## 反思
- 这学期/今年最重要的一两个感悟
- 价值观层面的（"人生不应该只有……"）

## 下一步
- 接下来想做什么 / 不再做什么
```

**落盘建议**：`note/zh-cn/年度总结/index.md`（用目录组织多文件）或单文件 `note/zh-cn/YYYY总结.md`。`tags: [conclusion]`，`series: 总结`。

---

## 2. 生活手记 (Life Jotting)

**适用场景**：日常流水、碎碎念、随手记录。

**真实样本**：`jotting/zh-cn/3月月总结.md`、`jotting/zh-cn/我的zellij使用/`

**大纲骨架**：

```markdown
## 这周/这个月发生了什么
- 3-5 件事，短的段落或列表

## 一些想法
- 看了什么、听了什么、想到了什么
- 允许 self-question：(？)

## 闲笔
- 看了什么番/剧/书/电影
- 遇到的人、喝过的酒、去过的地方
- 可以单独成段："这学期后面开始偶尔喝点酒……"
```

**落盘建议**：`jotting/zh-cn/<标题>.md`（短）或 `jotting/zh-cn/<标题>/index.md`（多文件）。**无** `series` 字段（jotting schema 没这字段）。

---

## 3. 技术对比 (Tech Comparison)

**适用场景**：横向对比多个库/框架/方法，给出选型建议。

**真实样本**：暂无直接样本——`Flow and Diffusion Model.md` 的章节结构可参考，但它是技术介绍**不是**横向下对比（review 指出该引用有误导）。本条模板属于「待用后补」：先照骨架写，写完找机会用一篇真实对比文回填样本。

**大纲骨架**：

```markdown
## 背景
- 我要解决什么问题 / 选型场景

## 候选清单
- 列 3-6 个候选，一段话介绍每个

## 横向对比表
| 维度 | A | B | C | D |
|------|---|---|---|---|
| ...  |   |   |   |   |

## 差异化分析
- 我们的项目/场景有什么特殊需求
- 哪条路满足、哪条不满足

## 结论
- 我们选了哪条，为什么
- 留个 follow-up：什么情况下会换路径
```

**落盘建议**：`note/zh-cn/<主题>/index.md`，必要时加 `tables/` 目录放对比表 markdown。`tags: [comparison]`，`series: <主题>`（可选）。

## 4. 项目记录 (Project Record)

**适用场景**：真实项目的进展、决策、踩坑、优化记录。

**真实样本**：`note/zh-cn/MiniMind-O CUDA Graph优化实录.md`、`note/zh-cn/MiniMind-O性能优化实录.md`、`note/zh-cn/SmolVLA接入实录.md`

**大纲骨架**：

```markdown
## 上一篇写到哪了
- 用 markdown 链接回上一篇，1-2 段交代上下文

## 这次的目标
- 上次到哪了，这次想打到哪

## 第一次尝试：失败得很彻底
- 贴原始报错
- 解释为什么失败

## 第二次尝试：……（可多次）
- 每次循环：方案 → 结果（数字）→ 反思

## 关键决策
- 哪个判断点把方向定下来

## 收尾
- 给个 checklist 或 SOP（可复用）
- 预告下一篇

```

**落盘建议**：`note/zh-cn/<项目>-<主题>/index.md` 或单文件。`tags: [...]` 按主题打，`series: <项目名>`（比如 `series: MiniMind-O`）。

---

## 5. 技术学习 (Tech Learning)

**适用场景**：读完一篇 paper / 学完一门课 / 啃完一个 codebase 的系统笔记。

**真实样本**：`note/zh-cn/CS188从搜索问题，MDP到RL.md`、`note/zh-cn/MiniMind预训练.md`、`note/zh-cn/Modern Robotics笔记 Chapter2-3.md`

**大纲骨架**：

```markdown
## 简介
- 这是什么（paper / 课程 / repo）
- 我为什么学它、用什么资源

## 第一部分：……（按章节/模块拆）
### 1.1 ……（用编号小标题）
- 定义 → 示例 → 我的理解

### 1.2 ……

## 第二部分：……

## 后续方向与总结
- 我接下来想用它做什么
- 哪些细节还没吃透
```

**落盘建议**：`note/zh-cn/<主题>/index.md` 或单文件（如果短）。`tags: [主题, 课程名]`，`series: <课程/paper 名>`（可选）。

---

## 6. 折腾记录 (Tinkering Record)

**适用场景**：刷机 / 部署 / 工具配置 / 环境搭建的踩坑流水。

**真实样本**：`note/zh-cn/obsidian折腾总结/index.md`、`note/zh-cn/ROS2人脸识别using pixi.md`

**大纲骨架**：

```markdown
## 我想达成什么
- 1-2 句话说清目标

## 尝试 1：方案 A
- 怎么做的
- 卡在哪（贴报错/截图）

## 尝试 2：方案 B
- ……

## 最终方案
- 哪个方案 work 了，关键命令/配置贴出来
- 可选：贴最终架构图（用 ![alt](images/xxx.png) 自动转 figure）

## 踩坑清单
- 列表形式，3-5 条值得记的

```

**落盘建议**：`note/zh-cn/<工具>-折腾总结/index.md`。`tags: [工具名, tinkering]`。可放 `images/` 集中图。

## 类型 → 集合映射速查

| 文章类型 | 集合 | series 字段 |
|---|---|---|
| 年度总结 | `note/` | `总结` |
| 生活手记 | `jotting/` | —（schema 无）|
| 技术对比 | `note/` | `<主题>` |
| 项目记录 | `note/` | `<项目名>` |
| 技术学习 | `note/` | `<课程/paper>` |
| 折腾记录 | `note/` | — |

**经验法则**：
- 长文 + 有结构 → `note/`
- 短文 + 流水账 → `jotting/`
- 不确定 → `note/`（更通用）
