# 写作风格指南 (Style Guide)

本文档从 `src/content/note/zh-cn/` 和 `src/content/jotting/zh-cn/` 下的真实文章提炼。

参考样本：
- `MiniMind-O CUDA Graph优化实录.md` — 项目记录
- `大一下学期总结.md` — 学期总结
- `CS188从搜索问题，MDP到RL.md` — 技术学习
- `obsidian折腾总结/index.md` — 折腾记录
- `3月月总结.md` — 生活手记

## 核心原则

### 1. 坦诚面对失败

失败值得用 1-2 段具体描述，**不**包装成"挑战"或"探索"。

> "修了一下 stream 问题，又来：`RuntimeError: During capture: encountered an autograd node.`"
> — MiniMind-O CUDA Graph 优化实录

要点：
- 贴原始报错（英文原文照贴不翻译）
- 给出失败的具体数字（"倒贴了 91ms"）
- 不用"不顺利"、"遇到一些困难"这种模糊词

### 2. 数字驱动

形容词给形容词，**具体场景给数字**：

- ❌ "显著提升" → ✅ "7.51× 端到端"
- ❌ "大量章节" → ✅ "74KB, 51 节"
- ❌ "持续优化" → ✅ "846ms → 320ms"

数字可以藏在括号里，也可以独立成段（"5 个 GPU 闸门全绿"）。

### 3. 中英混杂

技术词保留英文，不强行翻译：

| 中文 | 英文（保留）|
|---|---|
| 内核 | kernel |
| 启动开销 | launch overhead |
| 派生/分支 | fork |
| 单例 | subclass |
| 猴子补丁 | monkey-patch |
| 训练 session | session |
| 基准测试 | benchmark |
| 奖励（稀疏）| reward |

中英混着写是风格，**不是**翻译事故。

### 4. 口语化短句

长短交替，允许单句成段：

> "时间总是这样流过."
> "人生还有很长啊."

不要：
- ❌ "综上所述，本学期在多个维度均取得了长足的进步。"
- ✅ "这学期看了星际牛仔,漂流少年,冰海战记,怪奇物语.(阿谢拉特很帅)"

### 5. 交叉引用自己

大量用 markdown 链接指回/指向自己的其他文章：

```markdown
上一篇[《把 MiniMind-O 从 846ms 压到 320ms》](MiniMind-O性能优化实录.md)写到，25 轮自动实验把端到端生成从 846ms 压到 320ms 之后……
```

结尾常用「下一篇计划写……」承接未来内容。

### 6. 不强收尾

结尾可以是：
- 单句反思（"人生还有很长啊."）
- 预告下一篇（"下一篇计划写 SmolVLA 的接入……"）
- 给出可复用 checklist
- 留个疑问

**不要**用"综上所述"、"总而言之"、"本文介绍了"这种套话。

## 写作基因 (Writing Genes)

### 失败即素材

把每次 RuntimeError / crash / 失败都当成可写的故事节点，**不**隐藏。

### 数字颗粒度

报告到毫秒、字节、章节数、倍数。读者要的是可验证的细节，不是修饰。

### 因果链透明

写技术内容时，把「为什么这样做」的理由放在「怎么做」之前或并列。

### 自我吐槽用括号问号

用 `(？)` 表示不确定/自我怀疑（这是博客里验证过的真实手法，4 篇文章在用）：

> "发现自己闲下来，除了打球之外，好像没有什么想做的。也许我得充实下自己的爱好（？）"

**注意**：`~~删除线~~` 这个手法在已发布文章里**一次都没用过**，不要生成这种写法。（GFM strikethrough 虽然在 astro.config.ts 里启用了，但写作风格上没被采用。）

## 避免事项 (Avoid)

| 避免 | 改用 |
|---|---|
| 综上所述 / 总而言之 | 直接给结论或留开放 |
| 在这个……的时代 | 从具体场景/数字/反差切入 |
| 显著提升 / 大幅优化 | 给倍数或绝对数 |
| 翻译技术名词（"派生"） | 保留英文（fork）|
| "挑战与机遇并存" | 具体说挑战是什么、机会是什么 |
| 教科书式分点罗列 | 故事线 + 关键节点 |
| 把失败包装成"探索" | 直接说"失败了" |
| 感叹号！| 句号。或问号？|

---

## 句子节奏

- 短句为主，长短交替
- 单句成段允许（尤其在结尾或转折处）
- 段间用空行隔开，不用「首先、其次、最后」这种连接词
- 转折靠逻辑关系，不用「但是」、「然而」开段

## 真实语音样本

**开头（项目记录型）**：

> "上一篇[《把 MiniMind-O 从 846ms 压到 320ms》](MiniMind-O性能优化实录.md)写到，25 轮自动实验把端到端生成从 846ms 压到 320ms 之后，我已经没什么牌可以出了。"

**开头（生活手记型）**：

> "这个月进了组里，新来的特聘教授，在我们校内相比，资源还是比较多的。"

**收尾（项目记录型）**：

> "下一篇计划写 SmolVLA 的接入——同样是 5 条逐一打勾 + 4 个障碍一一打掉，但场景从 AR 文本+音频换成 VLA 视觉+动作，到时候再说。"

**收尾（生活手记型）**：

> "人生还有很长啊."

**失败描述**：

> "第一次 capture 尝试：失败得很彻底。"
